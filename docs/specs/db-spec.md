# Database & Persistence Specification (Vox v2)

> 🛑 **MANDATORY CONTEXT GATE FOR DATABASE LAYER:**
> Anyone touching, designing, reviewing, or querying the database persistence layer MUST read [Turso Database Engine — Technical Specification & Feature Reference](file:///home/addy/projects/apps/vox/docs/features/turso-database-engine.md) first.

## 1. Scope & Architectural Invariants

### 1.1 Strict Persistence Boundary Invariant
- **Sole Data Access Layer**: The `persistence/` module is the single source of truth for all database operations.
- **Zero Raw SQL Leakage**: No SQL queries, prepared statements, or database API calls are permitted anywhere in `ipc/`, `pipeline/`, or `services/`.
- **Public Facade**: `persistence/` exposes strongly-typed async Rust functions for all domain operations (e.g. `persistence::sessions::get_turns(conn, session_id)`).

### 1.2 Database & Connection Lifecycle (`open` vs `connect`)
- **Single Engine Instance**: `VoxDb` wraps an internal `Arc<turso::Database>` and is instantiated **exactly once** during application bootstrap via `VoxDb::open(&db_path)`. It is held as `Arc<VoxDb>` inside `AppState`.
- **Direct `open()` Banned**: Direct `VoxDb::open(&db_path)` calls outside application bootstrap and test fixtures are strictly banned.
- **Connection Vending (`VoxDb::connect()`)**: Rather than sharing a single `Arc<turso::Connection>` (which creates `concurrent use forbidden` contention due to per-connection operation gates), `VoxDb` acts as a connection factory via `state.db.connect() -> Result<turso::Connection>`.
- **Zero Disk Re-Opening**: Calling `state.db.connect()` creates a lightweight execution cursor attached to the already-open, running `turso::Database` engine. All vended connections share the exact same page cache, buffer pool, and WAL file.
- **Surface Connection Contracts**:
  - **IPC Command Handlers**: Obtain a fresh connection via `state.db.connect()?` for the duration of the handler invocation.
  - **Background Persistence Worker**: Holds its own dedicated write connection with MVCC conflict retry handling (`BEGIN CONCURRENT`).
  - **Memory Compaction / Ingestion**: Obtains an independent connection for atomic batch operations (`conn.transactional_batch(...)`).

### 1.3 Embedded Engine: Native Turso Engine (`turso` v0.8.0-pre.11)
- **Engine SSOT**: Vox utilizes the **`turso` crate v0.8.0-pre.11** as its embedded persistence engine (native Rust async I/O over Tokio, eliminating C SQLite dependencies and single-writer lock contention via native MVCC). All schema specifications and queries target Turso's native dialect and feature set (e.g., native `F32_BLOB` vectors).
- **Default Concurrency & Pragmas**:
  - `PRAGMA journal_mode = 'mvcc'`: Enables Multi-Version Concurrency Control, unlocking `BEGIN CONCURRENT` for optimistic non-blocking concurrent writes.
  - `PRAGMA foreign_keys = ON`: Strict referential integrity enforcement.
  - `conn.busy_timeout(Duration::from_millis(5000))`: Configured with phased exponential backoff (1ms, 2ms, ... max 100ms) on connection initialization to eliminate thread starvation during write spikes.
- **MVCC Conflict Retry Protocol**: Concurrent writes using `BEGIN CONCURRENT` detect overlapping row modifications at commit time. Callers must handle retryable errors (`Error::Busy`, `Error::BusySnapshot`, or conflict error strings) with a bounded exponential backoff retry loop (maximum 3 attempts).

### 1.4 Asynchronous Hot-Path Offload (`PersistenceEvent`)
To protect the voice hot-path latency budget (<200ms), all write operations generated by the voice pipeline are dispatched asynchronously via `mpsc::Sender<PersistenceEvent>`:

```rust
pub enum PersistenceEvent {
    SessionStarted {
        session_id: i64,
        timestamp_ms: u64,
    },
    SessionEnded {
        session_id: i64,
        timestamp_ms: u64,
    },
    TurnCompleted {
        session_id: i64,
        turn_id: u32,
        user_text: String,
        assistant_text: String,
    },
    ToolCallExecuted {
        id: String,
        session_id: i64,
        turn_id: u32,
        tool_name: String,
        tool_kind: String,
        arguments: String,
        result: Option<String>,
        is_error: bool,
        duration_ms: Option<u64>,
        created_at: u64,
    },
    UpdateSessionMetadata {
        session_id: i64,
        key: String,   // e.g. "title", "project_id"
        value: String,
    },
    Shutdown,
}
```

## 2. Target Database Schema

### 2.1 `projects` (Session Grouping)
Enables grouping and organizing conversation sessions.

| Column | Type | Constraints | Description |
|---|---|---|---|
| `id` | TEXT | PRIMARY KEY | Unique project slug/UUID (default: `'default'`) |
| `name` | TEXT | NOT NULL | User-visible display name |
| `created_at` | INTEGER | NOT NULL | Millisecond epoch timestamp |
| `updated_at` | INTEGER | NOT NULL | Millisecond epoch timestamp |

*Deletion Invariant:*
- Hard delete only. A project can only be deleted if it has zero sessions under it (enforced via `FOREIGN KEY (project_id) REFERENCES projects(id) ON DELETE RESTRICT`).

---

### 2.2 `sessions`
Represents an ongoing or historical conversation session.

| Column | Type | Constraints | Description |
|---|---|---|---|
| `id` | INTEGER | PRIMARY KEY | Monotonic session ID |
| `project_id` | TEXT | NOT NULL DEFAULT 'default' REFERENCES `projects(id)` ON DELETE RESTRICT | Associated project |
| `title` | TEXT | NULLABLE | Generated via `<title>` tag or user-renamed |
| `is_pinned` | BOOLEAN | NOT NULL DEFAULT FALSE | Quick access pin |
| `deleted_at` | INTEGER | NULLABLE | Soft delete timestamp (NULL if active) |
| `created_at` | INTEGER | NOT NULL | Session start millisecond epoch |
| `updated_at` | INTEGER | NOT NULL | Last turn millisecond epoch |

*Cascade & Deletion Boundaries:*
- **Soft Delete**: `UPDATE sessions SET deleted_at = ? WHERE id = ?`. Default queries filter `WHERE deleted_at IS NULL`.
- **Hard Delete**: `DELETE FROM sessions WHERE id = ?`. Cascades strictly down to `turns` and `session_compactions` (`ON DELETE CASCADE`). It does **NOT** delete extracted facts, vectors, or personal memory.

*Indexes:*
- `idx_sessions_project_updated`: `(project_id, updated_at DESC)`
- `idx_sessions_active`: `(deleted_at)`

### 2.3 `turns`
Stores finalized conversational turns.

| Column | Type | Constraints | Description |
|---|---|---|---|
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | Monotonic row ID |
| `session_id` | INTEGER | NOT NULL REFERENCES `sessions(id)` ON DELETE CASCADE | Parent session |
| `turn_id` | INTEGER | NOT NULL | Monotonic turn counter within session |
| `user_text` | TEXT | NOT NULL | Finalized STT transcript |
| `assistant_text` | TEXT | NOT NULL | Finalized synthesized assistant reply |
| `created_at` | INTEGER | NOT NULL | Millisecond epoch timestamp |

*Indexes:*
- `idx_turns_session_turn`: `UNIQUE (session_id, turn_id)`

### 2.4 `session_compactions`
Tracks rolling compaction-of-compactions passes and retains raw outputs for rollbacks.

| Column | Type | Constraints | Description |
|---|---|---|---|
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | Compaction run counter |
| `session_id` | INTEGER | NOT NULL REFERENCES `sessions(id)` ON DELETE CASCADE | Target session |
| `trigger_kind` | TEXT | NOT NULL | `'critical'`, `'soft'`, `'manual'` (user button), `'auto'` (session-end with auto-compaction on), or `'boot_auto'` (boot reconciliation with auto-compaction on) |
| `from_turn_id` | INTEGER | NOT NULL | Starting turn ID included in slice |
| `to_turn_id` | INTEGER | NOT NULL | Ending turn ID included in slice |
| `compaction_output` | TEXT | NOT NULL | Exact JSON output string from LLM (audit, context injection & rollback) |
| `status` | TEXT | NOT NULL | `'in_progress'`, `'completed'`, or `'failed'` |
| `error_msg` | TEXT | NULLABLE | Attributed failure message |
| `created_at` | INTEGER | NOT NULL | Millisecond epoch |
| `finished_at` | INTEGER | NULLABLE | Millisecond epoch |

*Indexes:*
- `idx_compactions_session_status`: `(session_id, status)`
- `idx_compactions_one_in_progress`: partial unique `(session_id) WHERE status = 'in_progress'` (mutual exclusion: at most one running compaction per session; concurrent duplicates fail at insert)

### 2.6 `memory_ingestion_queue` (Staging)
Temporary batch-processing staging queue for extracted facts awaiting deduplication.

| Column | Type | Constraints | Description |
|---|---|---|---|
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | Ingestion job ID |
| `session_id` | INTEGER | NULLABLE REFERENCES `sessions(id)` ON DELETE SET NULL | Source session provenance |
| `compaction_id` | INTEGER | NOT NULL REFERENCES `session_compactions(id)` ON DELETE CASCADE | Source compaction provenance |
| `type` | TEXT | NOT NULL | `'personal'`, `'objective'`, `'workdone'`, `'blocker'`, `'next_step'`, `'pitfall'` |
| `text` | TEXT | NOT NULL | Raw extracted fact text |
| `status` | TEXT | NOT NULL DEFAULT 'pending' | Strongly-typed lifecycle state |
| `retry_count` | INTEGER | NOT NULL DEFAULT 0 | Max 3 retry attempts |
| `error_msg` | TEXT | NULLABLE | Last error description |
| `created_at` | INTEGER | NOT NULL | Millisecond epoch |
| `processed_at` | INTEGER | NULLABLE | Millisecond epoch |

*Strongly-Typed Rust Lifecycle Enum (`QueueStatus`):*
- `Pending` (`'pending'`): Freshly inserted from compaction.
- `Stage1Processing` (`'stage1_processing'`): Atomically claimed by Stage 1 exact Jaccard dedup batch.
- `Stage1Done` (`'stage1_done'`): Passed exact dedup, awaiting embedding.
- `Stage2Processing` (`'stage2_processing'`): Atomically claimed by Stage 2 cosine embed/dedup batch.
- `Completed` (`'completed'`): Fully committed to `memory_facts`.
- `Failed` (`'failed'`): Exceeded 3 retry attempts.

*Indexes:*
- `idx_queue_status_type`: `(status, type)`

### 2.7 `memory_facts`
Permanent fact registry storing deduped, active and historical facts.

| Column | Type | Constraints | Description |
|---|---|---|---|
| `id` | TEXT | PRIMARY KEY | Fact ID: `fact_{timestamp}_{uuid}` |
| `session_id` | INTEGER | NULLABLE REFERENCES `sessions(id)` ON DELETE SET NULL | Provenance session |
| `compaction_id` | INTEGER | NOT NULL REFERENCES `session_compactions(id)` ON DELETE CASCADE | Source compaction provenance |
| `type` | TEXT | NOT NULL | `'personal'`, `'objective'`, `'workdone'`, `'blocker'`, `'next_step'`, `'pitfall'` |
| `text` | TEXT | NOT NULL | Deduped fact text |
| `status` | TEXT | NOT NULL DEFAULT 'active' | Strictly `'active'`, `'inactive'`, or `'consolidated'` |
| `created_at` | INTEGER | NOT NULL | Millisecond epoch |
| `updated_at` | INTEGER | NOT NULL | Millisecond epoch |

*Status Values:*
- `'active'`: Currently valid fact available for retrieval or consolidation.
- `'inactive'`: Deactivated fact (superseded by newer duplicate in dedup).
- `'consolidated'`: Personal fact merged into the `personal_memory` markdown document.

*Indexes:*
- `idx_facts_status_type`: `(status, type)`
- `idx_facts_session`: `(session_id)`

### 2.10 `session_tool_calls` (Cognitive Scratchpad Ledger)
Tracks all agentic tool calls, execution payloads, results, and timing. Decoupled from the spoken `turns` ledger to preserve speech-only audio replay while enabling precise multi-turn session rollback and tool execution audits.

| Field | Type | Constraints | Description |
| :--- | :--- | :--- | :--- |
| `id` | TEXT | PRIMARY KEY | Unique tool invocation identifier (UUID/ULID) |
| `session_id` | INTEGER | NOT NULL REFERENCES `sessions(id)` ON DELETE CASCADE | Associated session |
| `turn_id` | INTEGER | NOT NULL | Monotonic `u32` turn counter within session |
| `tool_name` | TEXT | NOT NULL | Tool identifier (e.g. `'respond_and_set_title'`, `'search_memory'`) |
| `tool_kind` | TEXT | NOT NULL | Operational category (`'terminal'` or `'non_terminal'`) |
| `arguments` | TEXT | NOT NULL | Serialized JSON parameters provided by model |
| `result` | TEXT | NULLABLE | Serialized JSON output returned by tool |
| `is_error` | BOOLEAN | NOT NULL DEFAULT FALSE | Failure indicator flag |
| `duration_ms` | INTEGER | NULLABLE | Wall-clock execution latency in milliseconds |
| `created_at` | INTEGER | NOT NULL | Millisecond epoch timestamp of invocation |

*Foreign Key Self-Healing & Memory Parity:*
- **Self-Healing Parent Row**: To guard against foreign key constraint violations if the initial `SessionStarted` persistence event was delayed or dropped by channel backpressure, write operations to `session_tool_calls` (via `PersistenceEvent::ToolCallExecuted`) and session title updates execute an idempotent self-heal before writing:
  `INSERT OR IGNORE INTO sessions (id, project_id, is_pinned, created_at, updated_at) VALUES (?, 'default', 0, ?, ?);`
- **Ephemeral Scratchpad vs Permanent Ledger**: Active in-memory working memory maintains intermediate tool interactions in a turn-local ephemeral scratchpad that is dropped at turn commit/cancellation. Only `session_tool_calls` preserves the durable execution history, guaranteeing 100% parity between active working memory and database-reconstructed sessions.
- **Cascade & Rollback Boundaries**:
  - **Session Deletion**: Deleting a session hard-cascades to `session_tool_calls` (`ON DELETE CASCADE`).
  - **Turn Rollback (Deferred)**: Interactive multi-turn rollback is architected for Phase 12.2+ (see `harness-spec.md §10`). When invoked, rewinding to turn $N$ executes atomic cleanup:
    `DELETE FROM session_tool_calls WHERE session_id = ? AND turn_id > N;`
    in lock-step with `DELETE FROM turns WHERE session_id = ? AND turn_id > N;`.

*Indexes:*
- `idx_tool_calls_session_turn`: `(session_id, turn_id)`
- `idx_tool_calls_created`: `(created_at DESC)`

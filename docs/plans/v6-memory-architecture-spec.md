# Vox v6 Hybrid Cognitive Memory Subsystem Architecture Specification

**Status**: Frozen Architectural Specification  
**Version**: 6.0  
**Target Systems**: `app/src-tauri/src/services/memory/` (Rust Backend)  

---

## 1. Core Architectural Philosophy

1. **Retrieval-First Design**: The memory system exists solely to improve future retrieval context. Ingestion creates ONLY information and edges that directly improve retrieval precision. If an edge is never useful during retrieval, it is never created.
2. **Decoupled Seed-and-Expand Pipeline**: Retrieval is seed-based. Collections independently declare their **Seed Generation Policy** (Deterministic SQL vs. Dense Vector Search). Retrieved seeds merge into a Unified Global Seed Pool before applying collection-specific **Graph Traversal Policies** for expansion.
3. **Strict 3-Class Collection Taxonomy**:
   - **Class C (Isolated Foundational)**: `Identity`, `Context`. Zero NLI, zero LLM, zero edge creation. 100% deterministic SQL retrieval.
   - **Class A (Operational State)**: `Constraints`, `Tasks`, `Goals`. Ingestion runs intra-collection NLI ONLY (`deberta-v3-xsmall`). Retrieval uses deterministic SQL seeds into the Global Seed Pool.
   - **Class B (Semantic Knowledge Graph)**: `Skills`, `Preferences`, `Projects`, `Experiences`, `Relationships`. Ingestion runs inter-collection LLM ONLY (`LFM2.5-230M` GGUF). Zero Class B intra-collection LLM passes. Intra-collection deduplication is handled in 0ms by Phase 1 hard-merge (`deduplication.rs`).
4. **Automatic Deterministic Inverse Edge Mapping**: Forward inter-collection edges generated by Class B LLM automatically trigger runtime creation of deterministic inverse edges in SQLite.
5. **No `SIMILAR` Graph Edges**: Near-duplicate facts are handled strictly via Phase 1 exact/near-duplicate hard deduplication (delete/merge). No `SIMILAR` graph edges exist in the database.

## 3. The 3-Class Collection Taxonomy

```
┌─────────────────────────────────────────────────────────────────────────────────────────────────┐
│                                  Vox v6 3-Class Taxonomy                                        │
├──────────────────────────────────┬────────────────────────────────┬─────────────────────────────┤
│ Class C: Isolated Foundational   │ Class A: Operational State     │ Class B: Semantic Knowledge │
│ (Deterministic SQL Only)         │ (Deterministic + Intra NLI)    │ (Vector Search + Inter LLM) │
├──────────────────────────────────┼────────────────────────────────┼─────────────────────────────┤
│ • Identity                       │ • Constraints                  │ • Skills                    │
│ • Context                        │ • Tasks                        │ • Preferences               │
│                                  │ • Goals                        │ • Projects                  │
│                                  │                                │ • Experiences               │
│                                  │                                │ • Relationships             │
└──────────────────────────────────┴────────────────────────────────┴─────────────────────────────┘
```

### Collection Class Ingestion & Seed Policies

#### Class C (Isolated Foundational)
* **Collections**: `Identity`, `Context`
* **Ingestion**: Zero NLI, Zero LLM, Zero edge creation. Isolated from graph traversal.
* **Retrieval Policy**:
  - `Identity`: 100% active facts fetched deterministically via SQL (`WHERE status = 'active'`).
  - `Context`: Time-window chaining fetched deterministically via SQL (`WHERE created_at >= window_start`).

#### Class A (Operational State)
* **Collections**: `Constraints`, `Tasks`, `Goals`
* **Ingestion**: Candidate search within same collection (`same_collection_candidate_search = 0.65`) $\rightarrow$ **Intra-collection NLI ONLY** (`deberta-v3-xsmall`).
* **Retrieval Policy**: Deterministic SQL (Latest $K = 5$ facts for `Tasks`/`Goals`; 100% active for `Constraints`). Seeds enter Unified Global Seed Pool.

#### Class B (Semantic Knowledge Graph)
* **Collections**: `Skills`, `Preferences`, `Projects`, `Experiences`, `Relationships`
* **Ingestion**:
  - Intra-collection: Phase 1 Cosine + Jaccard hard deduplication in 0ms. **Zero LLM passes.**
  - Inter-collection: Candidate search across connected collections (`inter_collection_candidate_search = 0.75`) $\rightarrow$ **Inter-collection LLM ONLY** (`LFM2.5-230M` GGUF).
* **Retrieval Policy**: BGE-M3 Dense Vector Search (`cosine_similarity = 0.70`, `top_k_facts = 5`). Seeds enter Unified Global Seed Pool and trigger bi-directional Seed-and-Expand graph traversal.

## 4. Connection Policy Matrix & Deterministic Inverse Edge Mapping

Class B LLM generates forward edges during ingestion. The Rust runtime automatically creates the deterministic inverse edge in SQLite without extra LLM passes:

| Source Collection (Class) | Allowed Target Collection (Class) | Forward Edge Type (LLM Generated) | Deterministic Inverse Edge Type (Runtime Created) |
| :--- | :--- | :--- | :--- |
| **`Projects` (Class B)** | `Tasks` (Class A) | `contains_task` | `belongs_to_project` |
| **`Projects` (Class B)** | `Goals` (Class A) | `drives_goal` | `supported_by_project` |
| **`Projects` (Class B)** | `Skills` (Class B) | `requires_skill` | `used_in_project` |
| **`Projects` (Class B)** | `Experiences` (Class B) | `yielded_experience` | `originating_project` |
| **`Skills` (Class B)** | `Experiences` (Class B) | `acquired_in` | `demonstrated_skill` |
| **`Preferences` (Class B)** | `Experiences` (Class B) | `shaped_by` | `influenced_preference` |
| **`Relationships` (Class B)** | `Experiences` (Class B) | `involved_in` | `included_relationship` |
| **`Relationships` (Class B)** | `Projects` (Class B) | `collaborates_on` | `project_contributor` |

*(Note: Class C `Identity` and `Context` are excluded from the Connection Policy Matrix. No edges connect to Class C).*

## 5. NLI Edge Resolution Mechanics Across Class A Collections

NLI runs **strictly on Class A intra-collection pairs** (`same_collection_candidate_search = 0.65`). However, **Edge Resolution Logic is Collection-Specific**:

```
┌─────────────────────────────────────────────────────────────────────────────────────────┐
│                     Class A Collection-Specific NLI Edge Resolution                      │
├───────────────────┬─────────────────────────────────────────────────────────────────────┤
│ Collection        │ NLI Conflict Resolution Behavior                                    │
├───────────────────┼─────────────────────────────────────────────────────────────────────┤
│ 1. Tasks          │ Auto-Resolve: CONFLICTS automatically converted to SUPERSEDES       │
│                   │ (Newer task supersedes older task in task state machine).           │
├───────────────────┼─────────────────────────────────────────────────────────────────────┤
│ 2. Goals          │ Auto-Resolve: CONFLICTS automatically converted to SUPERSEDES       │
│                   │ (Newer milestone supersedes older abandoned/pivoted goal).          │
├───────────────────┼─────────────────────────────────────────────────────────────────────┤
│ 3. Constraints    │ Preserve CONFLICTS: DO NOT auto-resolve to SUPERSEDES!              │
│                   │ Retained as unresolved CONFLICTS in DB. Rendered as prompt warning. │
│                   │ User can manually resolve in UI (updating source to 'USER').         │
└───────────────────┴─────────────────────────────────────────────────────────────────────┘
```

### Detailed Collection Breakdown

#### 1. `Tasks` (Operational State Machine)
* **NLI `CONFLICTS` Output** (e.g. *"Need to fill out passport form"* vs *"Passport mailed out expedited"*):
  - **Resolution**: **Auto-Resolved to `SUPERSEDES`**. The runtime sets `status = 'superseded'` on the older task row, and creates a `SUPERSEDES` edge pointing from the new task to the old task (`source = 'NLI'`).
* **NLI `SUPPORTS` Output** (e.g. *"Renew passport"* vs *"Take passport photo"*):
  - **Resolution**: `SUPPORTS` edge created (`belongs_to_task`).

#### 2. `Goals` (Milestone Progression)
* **NLI `CONFLICTS` Output** (e.g. *"Run marathon"* vs *"Knee injury, swim 5k instead"*):
  - **Resolution**: **Auto-Resolved to `SUPERSEDES`**. The runtime sets `status = 'superseded'` on the older goal row and creates `SUPERSEDES` edge (`source = 'NLI'`).
* **NLI `SUPPORTS` Output** (e.g. *"Publish Vox v1.0"* vs *"Achieve sub-100ms retrieval latency"*):
  - **Resolution**: `SUPPORTS` edge created (`sub_goal_of`).

#### 3. `Constraints` (Operational Guardrails)
* **NLI `CONFLICTS` Output** (e.g. *"Strictly gluten-free diet"* vs *"Blood sugar fine, eating sourdough again"*):
  - **Resolution**: **PRESERVED AS `CONFLICTS`** in database (`source = 'NLI'`).
  - **Retrieval Behavior**: Rendered in prompt context under `[Unresolved Contradictions]` warning block so the main LLM is explicitly aware.
  - **UI Resolution**: In the Vox UI, the user can inspect unresolved constraint conflicts and manually click "Resolve", creating a `USER_SUPERSEDES` edge (`source = 'USER'`).

## 6. Prompt Context Formatting & Provenance

Retrieved facts in `<user_profile>` **never contain internal database `fact_id`s**. They include clean, human-readable relative timestamps (`[2 weeks ago]`, `[Yesterday at 4 PM]`) and structural graph tree indentation:

```xml
<user_profile>
  [Identity]
  - Senior Staff Engineer located in Chicago, IL
  - Works remotely for a robotics startup

  [Constraints]
  - [2 weeks ago] Severe tree nut allergy (anaphylactic to walnuts and cashews)
  - [1 month ago] Strictly avoids refined sugars

  [Unresolved Contradictions]
  - [Unresolved Conflict] "Strictly avoids refined sugars" CONFLICTS WITH "Enjoys occasional bakery cake"

  [Active Tasks]
  - [Yesterday at 4 PM] Complete Gate 1 benchmark script

  [Semantic Knowledge Context]
  - [3 days ago] Project: Vox Memory Subsystem
    └─ (requires_skill) -> [1 week ago] Skill: Rust ONNX & GGUF
    └─ (contains_task)  -> [Yesterday] Task: Complete Gate 1 benchmark script
</user_profile>
```

## 7. Database Provenance Schema (`source` Column)

The `memory_facts` and `memory_relations` tables track provenance using the `source` column:

```sql
-- Provenance enum values for memory_relations
-- 'NLI'  : Automatically generated by deberta-v3-xsmall NLI model during Class A ingestion.
-- 'LLM'  : Automatically generated by LFM2.5-230M GGUF model during Class B ingestion.
-- 'USER' : Explicitly created or resolved by user via UI interaction (highest precedence).
```

When a relation has `source = 'USER'` (e.g. `USER_SUPERSEDES`), it overrides any `NLI` or `LLM` relation during edge resolution.

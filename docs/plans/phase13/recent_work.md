No Android input backend exists (X11/Wayland/XDO/libei are all desktop). Requires Batch 4's dictation exclusion (~14 files). Android `cargo check` gate therefore moved from Batch 1 to Batch 4.
- **Android Plan Corrections:** Audit of the Phase 12.2 plan refuted or amended 20+ claims — NDK is r29 not 27.2, no linker block was ever committed, `nexuss` needed repinning to **0.1.2** (not 0.1.1, which predates the char-boundary fix), `llama-cpp-sys` auto-disables OpenMP on Android so §7.1 needs no decision, `ort` **does** ship an `aarch64-linux-android` NNAPI artifact (the `nnapi` feature just isn't enabled), the Batch 4 LOC column was shifted by one row, 35 shortcuts not 51, and Batch 6's `WizardFooter`/`prefers-reduced-motion` items were already done.

- **Android Batch 4 Re-verification:** Audited a "Batch 4 complete" claim and found it overstated — the compile gate held, but **6 of 10** planned exclusions in plan §4.1 had never been made. - **⛔ Toolchain Trap — `SYSROOT` Breaks Android Clippy:** `rustc` **ignores** the `SYSROOT` env var; `clippy-driver` **honors** it. Because `cargo clippy` compiles this crate's build script for the *host* with `clippy-driver`, exporting `SYSROOT=<NDK>/.../sysroot` makes clippy hunt for host `x86_64` std inside the Android sysroot and fail at `E0463: can't find crate for std`. `cargo check --target` was unaffected, which is why the defect hid behind a green build. Verified by isolated reproduction.
- **Phase 0 — Verification Automation:** Added `app/src-tauri/scripts/verify-targets.sh` as the sole compile gate (both targets, sequential, `--release`, `-D warnings`, sysroot inlined, defensive `unset SYSROOT`). Replaced AGENTS.md §3's broken one-line gate. Added `.agents/rules/android-pitfalls.md` (10 confirmed traps, chiefly that `target_os = "linux"` is **false** on Android — 61 dead blocks across 14 files, while `cfg(unix)` is true). Gate was mutation-proven in both directions: survives a hostile `SYSROOT` export, and fails on a single injected unused import.

Mutation-verified in both directions.

- **Execution Order Established:** Phases 0→6 recorded. Batch 3 (APK on device) precedes Batch 2 (audio seam) so the seam is driven by observation rather than assumption. **Phase 2 — first `arm64-v8a` *release link*** is the highest-information action remaining: `cargo check` passes but nothing has been proven to *link*, and it settles the two claims still marked UNVERIFIED (`turso`/`libsql` §7.2, `ort` NNAPI §7.3).
- **Phase 2 — First `arm64-v8a` Link (APK Builds):** `cargo check` had been green all along but **compiles without linking**, so it structurally cannot see native-toolchain failures. Producing an actual binary surfaced six blockers, all in the native stack and none of them "Android is hard": (1) `clippy-driver` honors the `SYSROOT` env var while `rustc` ignores it, breaking every Android clippy run at `E0463`; (2) **duplicate `ggml_*` symbols** because llama.cpp is vendored twice (`llama-cpp-sys-4` and `chatterbox-rs`); (3) `crate-type = ["lib"]` emits an rlib, so Gradle found no `libvox_lib.so`; (4) bindgen had no sysroot inside Gradle; (5) chatterbox-rs passed no `CMAKE_TOOLCHAIN_FILE`, so CMake shadowed `CMAKE_SYSTEM_PROCESSOR` with the host value and ggml selected its x86 backend, failing on `-march=native`; (6) Gradle builds all four ABIs by default and `ort-sys` has no `armv7` binary. Result: a signed, installable **207.6 MB APK**, only `lib/arm64-v8a/`, `minSdk 24`, `targetSdk 36`, carrying `libvox_lib.so`, `libc++_shared.so`, `libonnxruntime.so` and three `libsherpa-onnx-*.so`. **`turso`/`libsql` and `llama.cpp` are now VERIFIED for arm64** — both were marked UNVERIFIED. Three rules worth keeping: a `.cargo/config.toml` rustflag is **silently overridden** by the `CARGO_TARGET_*_RUSTFLAGS` Tauri exports (inject from `build.rs` instead); cargo resolves `.cargo/config.toml` from **CWD, not `--manifest-path`**, and build scripts run with cwd inside `~/.cargo/registry/`, so `[env]` must live in `$CARGO_HOME/config.toml`; and Gradle cannot be driven standalone because its task dials back to the CLI over a WebSocket. Recorded as traps 11-15 in `.agents/rules/android-pitfalls.md`. `target/` trimmed 43 GB → 33 GB by deleting debug-profile artifacts and the unused `armv7` slice; the 3.6 GB `llama-cmake-cache` must be kept or rebuilds go from ~20 min to ~25 min.
- **Phase 3 — `ort` NNAPI + upstream chatterbox:** `ort` lacked the `nnapi` feature, but it could not simply be added to `[dependencies]`. `ort-sys/build/download/resolve.rs:126` requires an **exact** feature-set match against `build/download/dist.tsv`; there is exactly one `aarch64-linux-android` row and it is `nnapi`, while every desktop row is `none`/`webgpu`/`directml`/`cuda13`. So a global `nnapi` would resolve Android correctly and **break the desktop build**. It is now a `[target.'cfg(target_os = "android")'.dependencies]` entry, letting Cargo unify the feature into the Android graph only. A trap worth recording: **the rebuilt `libonnxruntime.so` is byte-identical** (sha256 `33847ad43bffe204`, 22,249,560 B) to the pre-change APK. With `nnapi` off, `resolve.rs` computes an empty `feature_set`, every Android candidate intersects it at 0, `0 == 0` passes the exact-match check, and it falls through to `candidates.first()` — the NNAPI artifact. The packaging was right by luck; the real defect was Rust-side, since `ort::ep::NNAPI` sits behind `#[cfg(feature = "nnapi")]` and was unselectable. **This change is verified by feature graph, not binary diff:** `cargo tree -e features -i ort-sys` yields 3 `nnapi` refs under `--target aarch64-linux-android` and **0** on desktop. Verified in the rebuilt APK: `ARM aarch64`, `NnapiExecutionProvider` present, no `GLIBC` undefined symbols, `liblog`/`libEGL` linkage. Separately, the chatterbox-rs Android toolchain fix (trap 14) is **upstream** as `c9d17bd` (`4d84eb3..c9d17bd`, pushed to `origin/main`), the local `[patch]` is deleted, `Cargo.toml` pins `rev = "c9d17bd"`, `Cargo.lock` resolves `git+...?rev=c9d17bd`, and `cargo metadata --locked` passes — **a fresh clone can now build the APK with no local submodule state**, closing the last reproducibility hole. Signed APK 207.7 MB; both targets clippy clean.
